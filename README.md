# OpenWRT NetCtrl

**Веб-панель управления флотом роутеров OpenWRT.**  
Мониторинг, SSH-терминал прямо в браузере, автологин в LuCI, карта роутеров, история метрик, уведомления в Telegram — всё в одном Docker-контейнере.

---

## Возможности

- 📊 **Мониторинг в реальном времени** — CPU, RAM, клиенты, аптайм, статус онлайн/офлайн
- 🗺️ **Карта** — отображение роутеров на карте по координатам
- 💻 **SSH-терминал в браузере** — полноценный xterm прямо в интерфейсе
- 🔑 **Автологин в LuCI** — открывает веб-интерфейс роутера одним кликом без ввода пароля
- 📈 **История метрик** — графики CPU/RAM/клиенты за 1 час / 6 часов / 24 часа / 7 дней
- 📦 **UCI конфиги** — снапшоты конфигурации, push-конфиг на несколько роутеров сразу
- 🔔 **Telegram-уведомления** — алерты при падении/восстановлении роутера
- 🤖 **Агент автообновления** — лёгкий sh-скрипт на роутере, heartbeat каждые 30 секунд
- 🏷️ **Группы и теги** — группировка роутеров по локациям
- 💾 **Бэкап БД** — скачивание базы данных одной кнопкой

---

## Требования

- Docker + Docker Compose (версия 2+)
- Доступ к роутерам по сети (SSH порт 22)
- На роутерах: OpenWRT 21.02 и выше

## Установка и запуск

### 1. Клонируй репозиторий

```bash
git clone https://github.com/imbazyx/openwrt-netctrl.git
cd netctrl
```

### 2. Запусти контейнер

```bash
docker compose up -d --build
```

Первый запуск занимает 1–2 минуты (скачивает `node:20-alpine`, устанавливает npm-пакеты).

### 3. Открой панель в браузере

```
http://localhost:3000
```

Пароль по умолчанию — `admin`. **Смени его сразу** (Настройки → Безопасность).

Авторизация включена по умолчанию. Токен хранится в `sessionStorage` браузера и
передаётся в заголовке `x-auth-token` (в WebSocket SSH — в query-параметре,
браузер не умеет слать заголовки в WS).

### 4. Проверь что всё работает

```bash
docker compose ps       # должен быть State: Up
docker compose logs     # должна быть строка: ✓ OpenWRT NetCtrl running
```

## Управление контейнером

```bash
# Запустить
docker compose up -d

# Остановить (данные сохраняются)
docker compose down

# Перезапустить
docker compose restart

# Посмотреть логи в реальном времени
docker compose logs -f

# Обновить после изменения файлов
docker cp ./client/index.html netctrl:/app/client/index.html   # без пересборки
# или полная пересборка:
docker compose up -d --build
```

> ⚠️ **НИКОГДА не используй `docker compose down -v`** — флаг `-v` удаляет volume с базой данных. Все данные будут потеряны безвозвратно. Используй только `docker compose down`.

## Добавление роутера — правильная процедура

Роутер можно добавить двумя способами: **вручную** через панель и **автоматически** через агента. Для полной функциональности нужны оба.

---

### Шаг 1 — Добавить вручную через панель

1. Открой `http://localhost:3000`
2. Нажми кнопку **«+ Добавить роутер»**
3. Заполни форму:
   - **Имя** — любое удобное название
   - **IP адрес** — IP роутера в твоей сети (например `192.168.1.1`)
   - **Локация** — текстовое описание места
   - **Модель** — модель устройства
   - **Группа** — выбери из существующих или создай новую в настройках
   - **SSH Пользователь** — обычно `root`
   - **SSH Порт** — обычно `22`
   - **SSH Пароль** — пароль root на роутере (тот же что при `ssh root@192.168.1.1`)
   - **Широта / Долгота** — для отображения на карте (можно кликнуть на карте во вкладке «Карта»)
4. Нажми **«Добавить роутер»**

После этого заработают: SSH-терминал, автологин в LuCI, ping, reboot, снапшоты конфига.

---

### Шаг 2 — Установить агента на роутер

Агент — лёгкий sh-скрипт. Отправляет heartbeat на сервер каждые 30 секунд (CPU, RAM, клиенты, аптайм).

**Сначала сгенерируй ключ регистрации в панели:**

Настройки → Система → «Ключ регистрации роутеров» → **Сгенерировать**. Скопируй ключ.
Пока ключ не задан, регистрация открыта — этого достаточно для обычной LAN, но не для публичного доступа.

**Узнай IP своей машины с Docker:**

```bash
ip route get 192.168.1.1 | awk '/src/{print $7}'
```

Например, получилось `192.168.1.100`.

**Зайди на роутер по SSH и выполни:**

```bash
wget -q --header="x-auth-token: <токен_панели>" \
  http://192.168.1.100:3000/agent/install.sh -O - | sh
```

Установщик положит агента в `/usr/bin/netctrl-agent`, создаст init-скрипт `/etc/init.d/netctrl`,
включит автозапуск и сразу запустит агента. Через 30 секунд роутер в панели станет **Online**.

Токен панели — тот, что вернул `/api/auth/login` (в веб-панели он лежит в `sessionStorage.authToken`).

**Проверка агента на роутере:**

```bash
# Посмотреть логи агента
logread | grep netctrl

# Проверить что агент запущен
ps | grep netctrl

# Текущий id и ключ роутера
cat /etc/netctrl/id /etc/netctrl/key
```

**Если ключ регистрации не задан в панели**, установщик откажется ставить агента.
Это защита от случайной установки в неправильном окружении.

Агент сам перерегистрируется, если роутер удалён на сервере или ключ сменился.
Интервал heartbeat берётся из настроек панели (по умолчанию 30 с).

## Автологин в LuCI

После того как добавил роутер с паролем, автологин в LuCI работает так:

1. На карточке роутера нажми меню **`···`**
2. Выбери **«Открыть LuCI»**
3. Откроется новая вкладка — роутер залогинится автоматически

> ℹ️ Для работы автологина на роутере должен быть установлен пакет `luci-mod-rpc`:
> ```bash
> opkg update && opkg install luci-mod-rpc
> ```

## SSH-терминал

1. На карточке роутера нажми меню **`···`** → **«SSH терминал»** или кнопку `>_`
2. Откроется окно терминала с анимацией подключения
3. После подключения — полноценный bash/ash прямо в браузере

Требования: роутер добавлен с правильным SSH-паролем, порт 22 доступен.

## Настройки панели

Раздел **Настройки** (значок ⚙ в меню):

### Telegram-уведомления

Получай алерты когда роутер падает или восстанавливается.

1. Создай бота через [@BotFather](https://t.me/BotFather), получи токен
2. Узнай свой Chat ID через [@userinfobot](https://t.me/userinfobot)
3. В настройках панели вставь **Токен** и **Chat ID**
4. Нажми **«Тест»** — должно прийти тестовое сообщение

### Авторизация панели

Авторизация **включена по умолчанию**. Пароль администратора по умолчанию — `admin`,
смени его при первом входе (Настройки → Безопасность, минимум 8 символов).

1. Задай пароль администратора
2. Токен перевыпускается автоматически при смене пароля
3. Отключить можно в настройках («Авторизация» выкл.) — только в доверенной сети

Токен передаётся заголовком `x-auth-token`. Значение в query-параметре `?token=`
больше не принимается — оно утекает в логи, историю браузера и Referer.
Исключение — WebSocket SSH (`/ws/ssh?token=…`), там браузер не умеет слать заголовки.

Под авторизацией закрыты в том числе LuCI-автологин, прокси к LuCI, WebSocket SSH,
скачивание бэкапа БД и установщик агента.

### Ключ регистрации роутеров

Настройки → Система. Секрет для эндпоинта `POST /api/routers/register`.
Пока пусто — регистрация открыта (обычная LAN). Задайте ключ перед публикацией панели наружу.

Каждому роутеру при регистрации выдаётся свой ключ; heartbeat агент обязан его предъявлять
в заголовке `x-router-key`, иначе сервер отвечает 401. Это значит, что чужим `id`
метрики не подделать.

### Что ещё закрыто

- SSH-пароли роутеров **никогда** не отдаются в `GET /api/routers` (только флаг `ssh_pass_set`).
  Очистка поля пароля при редактировании не затирает сохранённый пароль.
- Ошибки возвращаются без стек-трейсов.
- На логин и смену пароля стоит rate limit (10 попыток в минуту с одного IP),
  на регистрацию роутера — 30 в минуту.

### Интервалы

- **Интервал heartbeat** — как часто агент присылает метрики (по умолчанию 30 сек)
- **Таймаут офлайн** — через сколько секунд без heartbeat роутер считается офлайн (по умолчанию 120 сек)

## Карта роутеров

Чтобы роутер отображался на карте, нужно задать координаты:

**Способ 1 — при добавлении/редактировании роутера:**

**Способ 2 — через вкладку «Карта»:**

4. Нажми **«📍 Сохранить»**

## Бэкап базы данных

### Ручной бэкап

Кнопка в разделе Настройки → **«Скачать резервную копию БД»** — скачивает файл `netctrl-backup-ДАТА.db`.

### Через командную строку

```bash
docker cp netctrl:/app/data/netctrl.db ./data/netctrl_backup.db
```

### Автоматический бэкап (cron)

Добавь в crontab (`crontab -e`) на машине с Docker:

```
# Каждое воскресенье в 3:00
0 3 * * 0 docker exec netctrl sh -c "cp /app/data/netctrl.db /app/data/netctrl_$(date +\%Y\%m\%d).db" && docker cp netctrl:/app/data/netctrl_$(date +\%Y\%m\%d).db ~/backups/
```

### Восстановление из бэкапа

```bash
docker compose down
cp netctrl_backup.db ./data/netctrl.db
docker compose up -d
```

## Перенос на другую машину (например Vontar X3)

1. Скопируй папку проекта на новую машину:
   ```bash
   scp -r ./netctrl user@vontar:/home/user/
   ```

2. Скопируй данные (базу данных):
   ```bash
   scp ./data/netctrl.db user@vontar:/home/user/netctrl/data/
   ```

3. На новой машине:
   ```bash
   cd /home/user/netctrl
   docker compose up -d --build
   ```

4. Открой `http://IP_VONTAR:3000`

> ℹ️ Не забудь обновить адрес сервера в агентах на роутерах — переменная `NETCTRL_SERVER` в `/etc/rc.local` или через переустановку агента с новым IP.

## Устранение проблем

### Контейнер не запускается — конфликт имени

```
Error: The container name "/netctrl" is already in use
```

Решение:
```bash
docker rm -f netctrl
docker compose up -d
```

### SSH не подключается из панели

1. Проверь что пароль верный в карточке роутера (`···` → Редактировать)
2. Проверь доступность SSH из контейнера:
   ```bash
   docker exec netctrl node -e "
   const {Client}=require('ssh2');
   const c=new Client();
   c.on('ready',()=>{console.log('OK');c.end();});
   c.on('error',e=>console.log('ERR:',e.message));
   c.connect({host:'192.168.1.1',port:22,username:'root',password:'ПАРОЛЬ',readyTimeout:8000});
   "
   ```
3. Проверь сетевую доступность:
   ```bash
   docker exec netctrl ping -c 3 192.168.1.1
   ```

### Библиотеки не загружаются (Terminal is not defined)

Если в консоли браузера (F12) видишь `Uncaught SyntaxError: Unexpected token '<'` — скрипты загружаются локально вместо CDN. Скачай актуальный `index.html` из репозитория и замени:

```bash
docker cp ./client/index.html netctrl:/app/client/index.html
```

### Агент не регистрируется

```bash
# На роутере проверь:
logread | grep netctrl

# Проверь что сервер доступен с роутера (нужен заголовок с токеном):
wget -q --header="x-auth-token: <токен>" -O - http://IP_СЕРВЕРА:3000/api/auth/status
```

Типичные причины:

| Сообщение в логе | Причина |
|---|---|
| `registration failed: {"error":"bad agent key"}` | ключ регистрации в панели не совпадает с тем, что зашит в `/etc/init.d/netctrl` |
| `registration failed: {"error":"Too many requests"}` | больше 30 регистраций в минуту с одного IP |
| `heartbeat failed: {"error":"bad router key"}` | ключ роутера в `/etc/netctrl/key` не совпадает с серверным |
| `registration failed: {"error":"ip required"}` | не определился LAN-адрес (`ip addr show dev br-lan`) |

Если ключи разъехались — удали `/etc/netctrl/id` и `/etc/netctrl/key`, агент перерегистрируется сам.

### LuCI не логинится автоматически

Установи пакет на роутере:
```bash
opkg update && opkg install luci-mod-rpc
```

### Посмотреть что в базе данных

```bash
docker exec netctrl node -e "
const db=require('./db');
console.log(JSON.stringify(db.all('SELECT id,name,ip,ssh_user,ssh_pass,status FROM routers'), null, 2));
"
```

## API

Базовый путь — `/api`. Авторизация — заголовок `x-auth-token`, токен из `POST /api/auth/login`.
Агент роутера — заголовок `x-router-key`, ключ из ответа `POST /api/routers/register`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/login` | `{password}` → `{ok, token}` |
| GET | `/api/auth/status` | `{auth_enabled}` — открытый, для клиента |
| GET/PUT | `/api/settings` | настройки панели (без `auth_token`/`admin_password`) |
| PUT | `/api/settings/password` | `{current, next}` → `{ok, token}` |
| GET | `/api/agent-key` | ключ регистрации роутеров |
| GET/POST | `/api/groups` | группы роутеров |
| GET/POST | `/api/routers` | список / создание роутера (без `ssh_pass`) |
| PUT/DELETE | `/api/routers/:id` | правка / удаление |
| POST | `/api/routers/register` | регистрация агента → `{id, key}` |
| POST | `/api/routers/:id/heartbeat` | метрики агента → `{ok, interval}` |
| POST | `/api/routers/:id/ping` | TCP-пинг по SSH-порту |
| POST | `/api/routers/:id/reboot` | перезагрузка |
| POST | `/api/routers/:id/opkg-update` | `opkg update` |
| GET | `/api/routers/:id/packages` | список обновляемых пакетов |
| GET | `/api/stats` | сводка по флоту |
| GET | `/api/metrics/:id` | `?hours=` (1..720) — история метрик |
| GET | `/api/events` | `?limit=` (1..1000) — лента событий |
| GET/POST | `/api/snapshots` | снапшоты `uci export` |
| GET/DELETE | `/api/snapshots/:id` | один снапшот / удалить |
| POST | `/api/push-config` | выполнить команду на нескольких роутерах |
| GET | `/api/update-history` | история обновлений |
| GET | `/api/system` | версия, размер БД, счётчики |
| GET | `/api/backup/download` | файл БД (заголовок `x-auth-token`) |
| POST | `/api/telegram/test` | тест Telegram |
| GET | `/luci-login/:id` | автологин в LuCI |
| — | `/proxy/:id/*` | прокси к LuCI роутера |
| WS | `/ws/ssh?id=&token=` | SSH-терминал |

Неизвестный путь под `/api/` отдаёт JSON 404, а не HTML — иначе клиенты
молча парсят страницу вместо ответа.
